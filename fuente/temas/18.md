## 1. Lenguajes de programación

### 1.1. Concepto

Un **lenguaje de programación** es un **lenguaje formal** con un conjunto de **símbolos**, unas **reglas sintácticas** (cómo se combinan) y unas **reglas semánticas** (qué significan) que permite escribir instrucciones que un ordenador puede ejecutar.

Elementos de un lenguaje:

- **Léxico** (vocabulario): palabras reservadas, identificadores, literales, operadores, separadores.
- **Sintaxis**: reglas de construcción de las sentencias, definidas formalmente con gramáticas (notación **BNF** o EBNF).
- **Semántica**: significado de cada construcción (estática, comprobada al compilar; dinámica, en la ejecución).
- **Pragmática**: uso práctico y convenciones.

## 2. Clasificaciones de los lenguajes

### 2.1. Por su nivel de abstracción

| Nivel | Características | Ejemplos |
|---|---|---|
| **Lenguaje máquina** | Instrucciones en **binario** que la CPU ejecuta directamente; dependiente del procesador | 10110000 01100001 |
| **Lenguaje ensamblador** | **Mnemónicos** que corresponden **uno a uno** con las instrucciones máquina (MOV, ADD, JMP); requiere un **ensamblador**; dependiente de la arquitectura | x86 Assembly, ARM Assembly |
| **Lenguajes de alto nivel** | Cercanos al lenguaje humano y a la lógica del problema; **independientes** del hardware y **portables**; una instrucción equivale a muchas de máquina | C, Java, Python, C#, COBOL |

A veces se habla de **nivel medio** para C, por permitir acceso cercano al hardware (punteros, gestión de memoria) con construcciones de alto nivel.

### 2.2. Por generaciones

| Generación | Descripción | Ejemplos |
|---|---|---|
| **1GL** | Lenguaje **máquina** | Binario |
| **2GL** | **Ensamblador** | Assembly |
| **3GL** | Lenguajes **procedimentales o de alto nivel**: el programador indica **cómo** resolver el problema | FORTRAN, COBOL, BASIC, Pascal, **C**, C++, **Java**, C# |
| **4GL** | Lenguajes **orientados al problema**, **no procedimentales**: se indica **qué** se quiere, no cómo; productividad alta | **SQL**, generadores de informes y de aplicaciones, Natural, lenguajes de herramientas *low-code* |
| **5GL** | Basados en la **resolución de problemas con restricciones y lógica**, propios de la **inteligencia artificial** | **Prolog**, Mercury, OPS5 |

### 2.3. Por paradigma

| Paradigma | Idea | Lenguajes |
|---|---|---|
| **Imperativo** | Secuencia de **órdenes** que cambian el **estado** del programa (indica **cómo**) | — |
| — Procedimental o estructurado | Programa dividido en **procedimientos y funciones** | C, Pascal, COBOL, FORTRAN |
| — **Orientado a objetos** | **Objetos** con estado y comportamiento | Java, C#, C++, Python, Ruby, Smalltalk |
| **Declarativo** | Se describe **qué** se quiere obtener | — |
| — **Funcional** | Basado en **funciones matemáticas puras**, sin efectos secundarios, **inmutabilidad**, funciones de orden superior, recursividad | Haskell, Lisp, Scheme, Erlang, Elixir, F#, Clojure, Scala |
| — **Lógico** | **Hechos y reglas**; el motor de inferencia deduce las respuestas | **Prolog** |
| — De consulta | Consultas sobre datos | **SQL**, XQuery |
| **Orientado a eventos, a aspectos, concurrente** | Ver tema 17 | JavaScript, AspectJ, Go, Erlang |

La mayoría de los lenguajes actuales son **multiparadigma**: Python, JavaScript, C#, Kotlin, Scala o Java (desde Java 8, con expresiones lambda y *streams*).

### 2.4. Por la forma de ejecución

| Tipo | Funcionamiento | Ventajas | Inconvenientes | Ejemplos |
|---|---|---|---|---|
| **Compilados** | Un **compilador** traduce **todo** el código fuente a **código máquina** antes de ejecutarlo, generando un **ejecutable** | **Rapidez** de ejecución; detecta muchos errores antes de ejecutar; no hace falta distribuir el fuente | Hay que recompilar para cada plataforma; ciclo editar-compilar-ejecutar más lento | C, C++, **Go**, **Rust**, Fortran, Pascal |
| **Interpretados** | Un **intérprete** lee y ejecuta el código **instrucción a instrucción** en tiempo de ejecución | **Portabilidad**, flexibilidad, desarrollo rápido, ejecución interactiva | Ejecución más **lenta**; los errores aparecen al ejecutar | **Python** (CPython compila a *bytecode* internamente), **PHP**, Ruby, **Bash**, PowerShell, JavaScript (clásico) |
| **Híbridos (compilación a código intermedio)** | Se compila a un **código intermedio** (*bytecode*) independiente de la plataforma, que ejecuta una **máquina virtual**, a menudo con compilación **JIT** (*Just In Time*) a código nativo | **«Escribe una vez, ejecuta en cualquier parte»** con buen rendimiento | Necesita la máquina virtual instalada | **Java** (.class → **JVM**), **C#** y VB.NET (**CIL/MSIL** → **CLR** de .NET), Kotlin, Scala |

Hoy la frontera es difusa: los motores de **JavaScript** (V8) usan JIT, y existen compiladores **AOT** (*Ahead Of Time*) para Java (GraalVM) y .NET.

### 2.5. Por el sistema de tipos

| Criterio | Opciones | Ejemplos |
|---|---|---|
| **Momento de la comprobación de tipos** | **Estático**: los tipos se comprueban en **compilación** (errores detectados antes) / **Dinámico**: en **ejecución** (más flexible) | Estático: Java, C#, C, Go, Rust, **TypeScript**. Dinámico: Python, JavaScript, PHP, Ruby |
| **Rigor** | **Fuerte**: no permite operaciones entre tipos incompatibles sin conversión explícita / **Débil**: hace **conversiones implícitas** | Fuerte: Python, Java. Débil: JavaScript ("5" + 1 = "51"), PHP, C |
| **Declaración** | **Explícita** (int edad) / **Inferida** (var, let, auto) | — |

### 2.6. Por la gestión de la memoria

- **Manual**: el programador reserva y libera (malloc/free en C, new/delete en C++). Riesgo de **fugas de memoria** y errores de seguridad (desbordamientos de *buffer*, uso después de liberar).
- **Recolector de basura (*garbage collector*)**: libera automáticamente la memoria que ya no se usa (Java, C#, Python, Go, JavaScript).
- **Propiedad y préstamo (*ownership*)**: el compilador garantiza la seguridad de memoria sin recolector (**Rust**). Agencias como la NSA y CISA recomiendan lenguajes **seguros en memoria**.

### 2.7. Otras clasificaciones

- Por **propósito**: **generales** (Java, Python, C#) o **específicos de dominio** (**DSL**: SQL, HTML, R para estadística, MATLAB, VHDL).
- **Lenguajes de *script***: interpretados, para automatizar tareas o añadir comportamiento a otros programas (Bash, PowerShell, Python, JavaScript, Perl). Ver tema 31.
- **Lenguajes visuales o *low-code/no-code***: se programa mediante elementos gráficos (Scratch, Power Apps, OutSystems).

## 4. Características y técnicas de los lenguajes

### 4.1. Proceso de traducción

**Compilación**, fases de un compilador:

1. **Análisis léxico** (*scanner*): divide el texto en **componentes léxicos** (*tokens*): palabras reservadas, identificadores, números, operadores. Elimina espacios y comentarios.
2. **Análisis sintáctico** (*parser*): comprueba que los tokens siguen la **gramática** del lenguaje y construye el **árbol sintáctico**.
3. **Análisis semántico**: comprueba el **significado**: tipos compatibles, variables declaradas, número de parámetros. Usa la **tabla de símbolos**.
4. **Generación de código intermedio**.
5. **Optimización** del código.
6. **Generación de código objeto** (máquina).

Después, el **enlazador** (*linker*) une los módulos objeto y las **bibliotecas** (enlace **estático**, incluidas en el ejecutable, o **dinámico**, .dll/.so cargadas en ejecución) para producir el **ejecutable**. El **cargador** (*loader*) lo lleva a memoria.

Otros traductores: **ensamblador** (de ensamblador a máquina), **intérprete**, **transpilador** (de un lenguaje de alto nivel a otro: TypeScript → JavaScript), **preprocesador** (C: #include, #define), **descompilador** (de máquina a alto nivel; ingeniería inversa).

### 4.2. Tipos de errores

| Error | Cuándo se detecta | Ejemplo |
|---|---|---|
| **Léxico** | Compilación | Carácter no válido |
| **Sintáctico** | Compilación | Falta un punto y coma, paréntesis sin cerrar |
| **Semántico** | Compilación (estático) o ejecución | Sumar un texto y un número en un lenguaje fuertemente tipado |
| **De ejecución** (*runtime*) | Ejecución | División por cero, acceso a un índice fuera de rango, puntero nulo |
| **Lógico** | Pruebas | El programa funciona pero da resultados incorrectos |

### 4.3. Técnicas y características de los lenguajes modernos

- **Gestión de excepciones** (try/catch/finally).
- **Genéricos o plantillas** (List<Paciente>): estructuras reutilizables con comprobación de tipos.
- **Expresiones lambda** y funciones de orden superior (map, filter, reduce).
- **Programación asíncrona** (async/await, promesas, *futures*) y **concurrencia** (hilos, corrutinas, *goroutines*).
- **Anotaciones** o atributos (@Override, @Entity) y **reflexión** (inspeccionar el código en ejecución).
- **Módulos y paquetes**; **espacios de nombres** (*namespaces*).
- **Inyección de dependencias** (frameworks).
- **Programación segura**: validar las entradas, evitar la **inyección SQL** (consultas parametrizadas), escapar las salidas (XSS), no guardar secretos en el código, usar bibliotecas criptográficas probadas. Guías **OWASP** y **CERT**.
- **Convenciones de estilo** (PEP 8 en Python, convenciones de Java) y **código limpio** (*clean code*).

## 5. Herramientas y entornos de desarrollo

### 5.1. Entornos de desarrollo integrado (IDE)

Un **IDE** (*Integrated Development Environment*) reúne en una aplicación las herramientas del programador:

- **Editor de código** con resaltado de sintaxis, **autocompletado** (IntelliSense), plantillas y navegación por el código.
- **Compilador o intérprete** integrado y herramientas de **construcción**.
- **Depurador** (*debugger*): **puntos de ruptura** (*breakpoints*), ejecución **paso a paso**, inspección de variables y de la pila de llamadas.
- **Refactorización** automática (renombrar, extraer métodos).
- Integración con el **control de versiones** (Git), **pruebas** unitarias, bases de datos, contenedores.
- Hoy, también **asistentes de programación con IA** (GitHub Copilot, entre otros).

| IDE / editor | Fabricante | Lenguajes principales |
|---|---|---|
| **Visual Studio** | Microsoft | C#, .NET, C++ |
| **Visual Studio Code** | Microsoft (editor libre y gratuito, con extensiones) | Prácticamente todos |
| **IntelliJ IDEA** | JetBrains | Java, Kotlin |
| **Eclipse** | Eclipse Foundation (libre) | Java y otros con *plugins* |
| **NetBeans** | Apache (libre) | Java, PHP |
| **PyCharm** | JetBrains | Python |
| **Android Studio** | Google (basado en IntelliJ) | Kotlin, Java (Android) |
| **Xcode** | Apple | Swift (iOS, macOS) |
| **Jupyter** | Libre | *Notebooks* de Python, R (ciencia de datos) |

Otros: Rider (.NET), WebStorm (JavaScript), entornos en la nube (GitHub Codespaces).

### 5.2. Control de versiones

Registra los **cambios** en el código, permite volver a versiones anteriores y **trabajar en equipo** sin pisarse.

- **Centralizados**: un único servidor (CVS, **Subversion/SVN**).
- **Distribuidos**: cada desarrollador tiene una **copia completa** del repositorio (**Git**, creado por Linus Torvalds en 2005; Mercurial).

Conceptos y órdenes de **Git**:

| Orden | Función |
|---|---|
| `git init` / `git clone` | Crear un repositorio / copiar uno remoto |
| `git add` | Pasar cambios al **área de preparación** (*staging*) |
| `git commit` | Guardar una **instantánea** de los cambios con un mensaje |
| `git push` / `git pull` (`fetch` + `merge`) | Enviar / traer cambios del repositorio remoto |
| `git branch` / `git checkout` / `git switch` | Crear y cambiar de **rama** |
| `git merge` / `git rebase` | **Integrar** ramas |
| `git log`, `git diff`, `git status` | Historial, diferencias, estado |
| `git tag` | Marcar versiones (v1.0) |

Plataformas: **GitHub**, **GitLab** (muy usado en la Administración, autoalojado), Bitbucket, Azure DevOps. Flujos de trabajo: **GitFlow** (ramas *main*, *develop*, *feature*, *release*, *hotfix*), **trunk-based development**; revisión de código mediante **pull requests / merge requests**. **Versionado semántico**: MAYOR.MENOR.PARCHE.

### 5.3. Herramientas de construcción y gestión de dependencias

| Ecosistema | Herramientas |
|---|---|

| .NET | **MSBuild**, **NuGet** |
| JavaScript / TypeScript | **npm**, yarn, pnpm; empaquetadores (webpack, Vite) |
| Python | **pip**, Poetry, entornos virtuales (venv), conda |
| C/C++ | make, CMake |
| Contenedores | **Docker** (Dockerfile), Docker Compose |

Repositorios de artefactos privados: Nexus, Artifactory.

### 5.4. Herramientas de calidad del código

- **Análisis estático**: revisa el código **sin ejecutarlo** buscando errores, malas prácticas y vulnerabilidades: **SonarQube** (calidad, deuda técnica, cobertura, *quality gates*), linters (ESLint, Pylint, Checkstyle), herramientas **SAST** (seguridad).
- **Formateadores** (Prettier, Black).
- **Pruebas** unitarias y **cobertura** (JaCoCo, coverage.py).
- **Análisis de dependencias** (SCA: OWASP Dependency-Check, Snyk) y generación de **SBOM**.
- **Perfiladores** (*profilers*) para analizar el rendimiento.
- **Integración continua** que ejecuta todo lo anterior automáticamente (Jenkins, GitLab CI, GitHub Actions; tema 19).

### 5.5. Otras herramientas

- **Gestión de proyectos y tareas**: Jira, Redmine, Azure Boards, GitLab Issues.
- **Documentación**: Javadoc, Doxygen, Sphinx, **OpenAPI/Swagger** (APIs), wikis (Confluence).
- **Diseño y modelado**: herramientas **CASE** y UML (Enterprise Architect, StarUML, draw.io).
- **Herramientas *low-code***: Power Apps, OutSystems, Mendix.

## 6. Ideas que más caen en el examen

> - Niveles: **máquina**, **ensamblador** (mnemónicos, 1:1 con la máquina) y **alto nivel**.
> - Generaciones: 1GL máquina, 2GL ensamblador, **3GL procedimentales** (C, Java), **4GL** no procedimentales (**SQL**), **5GL** lógicos (**Prolog**).
> - Paradigmas: **imperativo** (procedural, OO) y **declarativo** (funcional, lógico, SQL).
> - **Compilado** (C, Go, Rust), **interpretado** (Python, PHP, Bash), **híbrido** (Java → bytecode → **JVM**; C# → **CIL** → **CLR**), con **JIT**.
> - Tipado **estático** (Java, C#, TypeScript) / **dinámico** (Python, JavaScript); **fuerte** / **débil**.
> - Compilador: **léxico → sintáctico → semántico → código intermedio → optimización → código objeto**; después el **enlazador**.
> - C (1972, Ritchie), Java (1995, Sun/Oracle), JavaScript (1995, ECMAScript), C# (2000, Microsoft), Python (1991), Kotlin (Android), Swift (iOS).
> - **IDE** = editor + compilador + depurador + más. VS Code, Visual Studio, IntelliJ, Eclipse.
> - **Git**: distribuido, de Linus Torvalds (2005). add → commit → push.
> - Maven/Gradle (Java), npm (JavaScript), pip (Python), NuGet (.NET). **SonarQube**: calidad del código.
